Tacticus-tools — flux runners & mirror

Cartographie des runners qui co-existent côté agent Frida, leur cycle de vie, et les actions utilisateur qui les manipulent. Ce document reflète l'état après l'étape 1+2+3 du refactor (rename liveRunner, watchedRunners, mirror.source, AUTO-PLAY déplacé sur le board).

Live runner (in-game battle) Build runner (launch standalone) Mirror runner (sandbox)

1. Les 3 rôles

Rôle Slot Cardinality Source / créé par Tag origin dans state.log
Live state.liveRunner 0 ou 1 main-pump détecte le runner créé par Tacticus quand l'utilisateur lance une bataille in-game "live"
Build runnerRegistry.byId (Map keyed by runnerId) 0..N launch.initRunner — désérialise une BattleConfiguration archivée et build un IdunRunner standalone <runnerId> (number)
Mirror simState.mirror avec source: { kind, runnerId? } 0 ou 1 simMirror({ source }) — build un nouveau standalone depuis la BattleConfiguration de la source, replaye les messages capturés correspondants n/a (le mirror n'émet pas vers state.log)
Garde « Live always required » — toute opération mirror exige que state.liveRunner !== null, même mirror sur build : les services live (StreamDispatcher, AiControl binding, Zenject) sont nécessaires aux hooks que les runners build réutilisent. Sans live in-game, on refuse côté serveur avec blockReason: "no live runner".

2. Cycle de vie

stateDiagram-v2 [*] --> NoLive NoLive --> LiveOnly: launch in-game battle LiveOnly --> NoLive: battle end LiveOnly --> LiveAndBuilds: launch initRunner LiveAndBuilds --> LiveOnly: dispose all builds LiveAndBuilds --> LiveAndBuilds: more builds LiveOnly --> MirrorLive: simMirror source=live LiveAndBuilds --> MirrorLive: simMirror source=live LiveAndBuilds --> MirrorBuild: simMirror source=build MirrorLive --> LiveAndBuilds: simReset MirrorBuild --> LiveAndBuilds: simReset MirrorLive --> MirrorBuild: switch source MirrorBuild --> MirrorLive: switch source MirrorBuild --> AutoPlaying: AUTO-PLAY AutoPlaying --> MirrorBuild: STOP or stage finished

Transitions clés

  • Détection live — le hook IdunGameViews.Update (main-pump.ts) lit le runner dans le View ; si différent de state.liveRunner ⇒ swap, clear state.log, réinstall recorder.
  • Création build — launch.initRunner({configJson}) désérialise la config, build un runner via le 2-arg ctor, l'ajoute au runnerRegistry ET dans state.watchedRunners.set(runner, runnerId) pour que le recorder le couvre.
  • Mirror swap — simMirror({ source }) drop l'ancien (gcRoot.remove + simState.mirror=null), build un nouveau via buildMirrorFromSource(src), replaye state.log[] filtré par originRunnerId === target.

3. Recorder (multi-watch)

flowchart TD A["runner.Apply hook (gshared)"] --> B{"args[0] in watchedRunners ?"} B -- no --> X[skip] B -- yes --> C["lookup origin: live or runnerId"] C --> D["snapshotMt per-runner (MtCache)"] D --> E["push LogEntry: src=top, originRunnerId=origin"] E --> F["pushApply live"] F --> G[invoke runner.Apply native] G --> H["onLeave: popApply + applyToMirror"] H --> I{"mirror.source === entry.originRunnerId ?"} I -- no --> J[skip this entry on mirror] I -- yes --> K["restoreMt mirror + runner.Apply mirror"]

Le recorder est unique mais multi-cible : le filter watchedRunners remplace l'ancien args[0].equals(runnerSnapshot). Le LogEntry est tagué avec originRunnerId pour que applyToMirror ne replaye que les entries de la source courante du mirror.

5. Gardes serveur

simMirror applique deux gardes cumulatives :
  1. state.liveRunner !== null (« Live always required »)
  2. sourceRunner._state.stage === 1 (Running) — le runner cible doit être en bataille engagée
simRunAiTurn n'accepte que les mirrors de source live. Pour un mirror build, le bon outil est AUTO-PLAY (boucle simAutoPlayStep).
simSaveLiveConfig ne peut sauvegarder que le live runner — un build a forcément été créé à partir d'une config déjà archivée, donc le re-archiver n'a pas de valeur.

7. Replay-bundle (download au clic 🪞)

Le clic MIRROR NOW sur le panel Sim télécharge en plus un fichier replay-<ts>-msgsN.json contenant config + seed + messages[] Newtonsoft-serialisés avec PRNG snapshots. Suffit pour reconstruire offline via buildRunner(cfg, seed) + DeserializeObject + restoreMt + Apply en boucle.
